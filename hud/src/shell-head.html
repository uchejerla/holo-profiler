        How the score works

        Completeness35%

        Share of cells that hold a value. Empty cells, whitespace and placeholders such as N/A, NULL or "none" count as missing.

        Validity30%

        Share of values that pass the check for the column's inferred type: email, phone, ZIP, US state, date, number, UUID, URL. Negative values in amount columns and future dates in event columns (loss, report, birth) also fail.

        Uniqueness20%

        Scored only for likely key columns (IDs, codes, UUIDs): distinct values divided by filled values. At file level it also discounts exact duplicate rows.

        Consistency15%

        Share of values in the column's dominant format, without case or spacing variants or stray spaces. At file level it also counts rows that break inferred cross-field rules, such as a report date earlier than the loss date.

        File score

        Half comes from the weighted dimensions above and half from the share of clean records, so a few bad columns spread across many rows pull it down. Each critical issue then takes off 4 points, up to 20. Bands: 90 and above is good, 75 to 90 is fair, below 75 is poor.

        Rules score

        Half is the pass rate across active rules, weighted by severity (critical 4, high 3, medium 2, low 1). Half is the share of rows that pass every active rule. Each failing critical rule takes off 4 points, up to 20. Suggested rules count until you reject them. Same bands as the file score.

        Column scores

        Each column's score is the weighted average of the dimensions that apply to it; weights are rescaled when uniqueness does not apply. Column and dimension bands are stricter: 99 and above is good, 95 to 99 is fair, below 95 is poor.

        Outliers use 3×IQR fences, computed on a log scale for right-skewed amounts, and are reported as issues without lowering the score. Files over 200,000 rows are profiled on a random sample of 200,000 rows, and rules run on that same sample. Clean records are rows with no missing, invalid or duplicated value and no cross-field violation. Read the issues list alongside the score: a critical problem can sit in only a few rows.
